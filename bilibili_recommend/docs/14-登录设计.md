# 14 登录设计

本文记录用户注册、登录、登出功能的需求和安全约定。

## 14.1 登录方式

第一版采用账号密码登录，不接入第三方登录。

```text
用户名 + 密码
注册、登录、登出
```

## 14.2 功能需求

### 注册

- 用户输入用户名、密码和确认密码。
- 确认密码必须与密码一致。
- 用户名唯一。
- 密码加密后存储。
- 注册时自动生成注册时间。
- 注册时使用默认头像。
- 注册成功后进入登录状态或跳转登录页。

### 登录

- 用户输入用户名和密码。
- 验证成功后保持登录状态。
- 失败提示统一为“用户名或密码错误”。

### 登出

- 前端删除 JWT。
- 后端不主动使 Token 失效。

### 保持登录状态

- 用户刷新页面或下次打开时保持登录。
- Token 未过期时不需要重新登录。
- Token 过期后返回 401，前端跳转登录页。

## 14.3 安全约定

- 密码使用 Argon2id 哈希算法存储，不保存明文。
- 登录状态使用 JWT，过期时间 7 天。
- Token 保存在前端 localStorage。
- 注册和登录输入使用 Pydantic 校验。
- SQL 查询使用参数化。
- 数据库配置通过 `.env` 管理。
- 登录失败按照锁定规则限制尝试次数。

## 14.4 状态码约定

| 状态码 | 场景 |
| --- | --- |
| 201 | 注册成功 |
| 200 | 登录、登出、获取用户信息成功 |
| 400 | 参数错误、用户名或密码错误 |
| 401 | 未登录 |
| 409 | 用户名已存在 |

## 14.5 接口幂等性

| 接口 | 幂等性 | 处理方式 |
| --- | --- | --- |
| 注册 | 非幂等 | 用户名唯一约束，重复注册返回 409 |
| 登录 | 接近幂等 | 重复登录无害，限制失败次数 |
| 登出 | 幂等 | 重复登出结果仍为未登录 |
| 获取用户信息 | 幂等 | 只读 |

## 14.6 前后端职责

```text
后端：
  判断用户身份
  返回状态码和响应数据
  阻止未授权数据泄露

前端：
  收到 401 后跳转登录页
  提交时禁用按钮防止重复点击
  根据状态码显示提示
```

## 14.7 用户表

```text
users
  id            主键
  username      用户名，唯一
  password_hash 密码哈希
  avatar        头像地址
  created_at    创建时间
```

## 14.8 保持登录状态的实现

采用 JWT 7 天过期，Token 保存在前端 localStorage。

```text
前端启动：
  从 localStorage 读取 Token
  有 Token：保持登录状态
  无 Token：跳转登录页

每次请求：
  请求头携带 Authorization: Bearer <token>

后端：
  验证 Token
  有效：正常返回
  无效或过期：返回 401

前端收到 401：
  清除 Token
  跳转登录页
```

## 14.9 账号规则与登录限制

### 用户名规则

```text
长度：3 到 20 位
允许字符：英文字母、数字、下划线
首字符：必须是英文字母
不允许中文
用户名唯一
```

### 密码规则

```text
长度：8 到 64 位
必须同时包含字母和数字
密码加密后存储
```

### 登录失败锁定

```text
同一账号连续失败 5 次，锁定 30 秒
之后每再失败 2 次，锁定时间翻倍
锁定时间上限为 30 分钟
锁定期间即使密码正确也拒绝登录
```

锁定时间示例：

```text
5 次失败  -> 锁定 30 秒
7 次失败  -> 锁定 60 秒
9 次失败  -> 锁定 120 秒
11 次失败 -> 锁定 240 秒
13 次失败 -> 锁定 480 秒
15 次失败 -> 锁定 960 秒
17 次失败 -> 锁定 1920 秒，超过上限，按 30 分钟处理
```

锁定状态下登录失败返回 `429 Too Many Requests`。

锁定状态可以存储在数据库表中，方便重启后仍然保留；本地原型也可以先使用内存存储。

## 14.10 用户信息与头像

- 注册时使用默认头像。
- 注册时间在创建用户时自动生成。
- 用户登录后可在个人主页修改头像。
- 修改头像通过更新用户信息接口完成。
